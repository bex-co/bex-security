## Objective

Replace trust in model-authored progress and coverage with host-verified review evidence, fixing the concrete false-completion failure without introducing a Muse-only policy.

## Context

- A reproduced run emitted progress for a sparse review and then jumped directly to the full inventory.
- The host currently validates marker syntax but not whether completed files were actually reviewed.
- The existing inventory, coverage, and scan-contract machinery should remain authoritative.

## Steps

1. Bind progress to the authoritative in-scope inventory and deduplicated review evidence.
2. Reject or ignore completed counts that lack corresponding reviewed-file evidence.
3. Prevent complete coverage when inventory entries are missing, validation is unresolved, or findings reference excluded paths.
4. Apply the same rules to every ACP agent and preserve existing public CLI syntax.

## Acceptance criteria

- [ ] A synthetic `850 -> full inventory` marker jump without evidence cannot produce full progress or complete coverage.
- [ ] A finding on an explicitly excluded path fails completion validation.
- [ ] Valid evidence from any supported ACP agent advances progress monotonically.
- [ ] No new public command, flag, environment variable, or default is added.

## Out of scope

- Requiring every file to produce a finding or verbose receipt artifact.
