## Objective

Exercise the fixed adapter as a real package in Bex and remove Muse-specific event, approval, and workspace compensation from the generic scan path.

## Context

- Bex should know how to launch and select Muse, but it should not know Muse JSONL payloads or repair adapter event shapes.
- A local package tarball allows repeated integration testing without publishing intermediate broken npm versions.

## Steps

1. Pack the adapter from `.internal/muse-code-acp` and install the tarball into the TypeScript SDK workspace.
2. Route Muse through the same ACP event handling and capability negotiation used by other agents.
3. Keep only unavoidable launch/configuration mapping in the Muse driver.
4. Run the adapter and progress integration tests against the packed artifact.

## Acceptance criteria

- [ ] Bex integration tests run against the packed adapter rather than source-only mocks.
- [ ] Bex contains no Muse JSONL parsing or Muse-specific command-output reconstruction.
- [ ] Codex, Claude, Kimi, and Muse flow through the common event consumer.
