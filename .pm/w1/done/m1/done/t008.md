## Objective

Confirm that normalized ACP events, capability states, progress, usage availability, failures, and completion semantics are represented consistently by the Bex SDK and user-facing CLI/dashboard.

## Context

- The concrete failure crossed the adapter, SDK event stream, and terminal dashboard.
- Muse must not receive a special display contract; the same normalized states should render for every agent.

## Steps

1. Compare adapter events with SDK observer callbacks and CLI rendering for all supported agents.
2. Verify unavailable usage/cost, approval failure, cancellation, partial coverage, and successful completion shapes.
3. Add behavioral assertions for any mismatch.

## Files

- `sdk/typescript/src/acp-adapter.ts`
- `sdk/typescript/src/api.ts`
- `sdk/typescript/src/cli.ts`
- `sdk/typescript/tests-ts/acp-adapter.test.ts`
- `sdk/typescript/tests-ts/api.test.ts`
- `sdk/typescript/tests-ts/cli.test.ts`

## Acceptance criteria

- [x] Equivalent ACP states render equivalent SDK and CLI states across agents.
- [x] Muse-specific details do not leak into public progress or error formats.
- [x] Partial and complete coverage are visually and semantically distinct.

## Verification

- The ACP, API, CLI, worker-progress, and scan-activity suites passed 352 tests with two intentional skips under the required Python runtime.
- The dashboard, contract, and comparison suites passed another 101 tests with three intentional skips, including usage/cost unavailable states and distinct partial/complete coverage behavior.
- Inspection confirmed normalized events and host fallback are generic; Muse-specific code remains limited to launch, session configuration, authentication guidance, and model selection.

## Out of scope
