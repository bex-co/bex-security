## Objective

Make `@bex-co/muse-code-acp` present Muse as a lossless, non-hanging ACP agent so Bex consumes standard ACP events and capabilities rather than compensating for Muse internals.

## Context

- `ToolCallTracker` has the completed Bash command and output but currently exposes them in a shape that generic clients may not recognize.
- Muse 0.2.1 headless has no interactive approval callback; an `approval_wait.effect.started` event must never wait forever in a non-interactive ACP turn.
- Muse supports one workspace root and must advertise directory limitations honestly.
- Bypass-approval mode retains the OS sandbox and is distinct from `--yolo`.

## Steps

1. Normalize completed Bash calls into stable ACP input/output fields while retaining streamed content.
2. Map headless session modes so non-interactive prompts cannot deadlock; fail clearly when a requested permission model cannot be satisfied.
3. Correct capability advertisement for workspace roots, resume/load, usage, cancellation, and permissions.
4. Preserve target read-only and scan-output writable behavior without disabling the OS sandbox.
5. Make all t001 conformance tests pass in the adapter repository.

## Acceptance criteria

- [ ] Generic ACP clients receive command, output, exit status, model/effort, usage, cancellation, and terminal state without parsing Muse JSONL.
- [ ] A headless approval scenario resolves or fails promptly and never hangs.
- [ ] Scan output is writable while repository source remains read-only under the Muse sandbox.
- [ ] No unsafe `--yolo` fallback is enabled.

## Out of scope

- Adding Bex-specific scan orchestration to the Muse adapter.
