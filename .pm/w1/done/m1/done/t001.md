## Objective

Turn the reproduced Muse failures into adapter-neutral conformance tests before changing implementation, so fixes land at the correct layer and remain comparable across supported agents.

## Context

- Muse Bash completion currently reconstructs command arguments from completion output rather than the initial ACP tool call.
- Muse headless approval waits are internal to `muse exec` and can leave an ACP prompt unresolved.
- Workspace roots, model/effort, usage, cancellation, and terminal states must be represented honestly through ACP capabilities and events.
- Bex must not depend on Muse JSONL record shapes.

## Steps

1. Extend the ACP fixture/conformance suite with command output, progress marker, permission, workspace, usage, cancellation, and failure cases.
2. Run the same applicable assertions against Codex, Claude, Kimi, and Muse adapters.
3. Preserve unsupported capabilities as explicit negotiated results rather than simulated success.

## Acceptance criteria

- [ ] Tests reproduce the raw-output-only Bash event and headless approval failure seen locally.
- [ ] Tests assert a common normalized event contract without importing Muse implementation details into Bex.
- [ ] Existing Codex, Claude, and Kimi adapter cases remain green.

## Out of scope
